# 经验球行为与验证

经验球优化默认启用，主要在服务端生效。联机时，客户端与服务端安装相同版本的 Core。

## 玩家会看到的变化

| 场景 | 行为 |
| --- | --- |
| 一次奖励 100 万经验 | 直接生成一个包含全部经验的球。 |
| 附近生成多个普通球 | 1 米内合并，减少实体数量；超过整数上限时保留独立球。 |
| 接触一批经验球 | 每位玩家每 tick 最多处理 32 次拾取，下一 tick 继续。 |
| 装备带有经验修补 | 保留原版选装备与修补效果，剩余经验进入玩家经验条。 |
| EnderIO 经验收集器容量不足 | 按整点经验存入流体，余量留在原球中。 |
| 保存或重载大球 | 完整数值保留；使用原版整数实体数据同步。 |

吸引范围与拾取碰撞范围沿用原版。普通球保留经验事件；取消拾取、修改经验量或修改等级的事件继续生效。合并后，逐球事件会以整个经验包为单位触发，按球计数或取整的其他模组效果可能改变触发粒度。

## 合并边界

只合并原版经验球类型，且单球计数为 1、默认生命值、未过期、没有名称、实体标签或持久数据，并保持默认重力与可受伤状态。自定义球和旧存档中的计数球不参与普通合并。

使用有界的空间缓存和弱引用，每个维度最多记录 8,192 个位置；每次查找最多检查附近 27 个缓存位置。周期合并复用缓存，不执行全世界实体扫描。拾取复用原版碰撞列表。

## 兼容与存档

本版本适配 Minecraft 26.1.2，以及 Curios 15 的饰品修补与 EnderIO 9 的经验收集器。两个适配均为可选：未安装对应模组时，Core 可独立运行。旧版其他 Minecraft 版本的 Botania、Industrial Foregoing 适配代码没有直接加载到本版本；新增对应模组时，需要按实际版本另行适配和验证。

超过 32,767 点的大球以 `SISEBulkXp` 整数保存，单球计数为 1。同时保存原版可读取的「1 点 × 总数」表示，移除 Core 后仍可保留总经验，拾取方式恢复为原版计数球。等级精度修复仅应用于原版经验曲线，并检查经验事件处理后的结果。

## 排查与验证

添加 JVM 参数 `-Dsise.core.xp.disabled=true` 并重启，可关闭合并、单球奖励、快速拾取和等级精度修复。大球存档保护、整数溢出保护和已有大球的安全修补、收集仍生效。

```powershell
.\gradlew.bat build runGameTestServer
```

GameTest 验证百万点奖励与一次领取、十万小球合并、整数上限、特殊球保护、存档与实体数据编码、0 到 1000 级精确边界、修补余量、经验事件、两位玩家领取保护、每 tick 拾取预算和回退开关。

验证可选模组时，传入存放其 JAR 的目录：

```powershell
.\gradlew.bat runGameTestServer -PxpCompatFixtures=<模组目录>
```

该选项只加载名称匹配 `curios-*.jar`、`enderio-*.jar` 的本地测试依赖，不把它们打包进 Core。Curios 检查最大整数经验下的修补与余量；EnderIO 检查容量仅剩 39 单位时，只消耗 1 点经验并保留余量。
