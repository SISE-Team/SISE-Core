# 汉化维护

**改好一条文本，保留它的来源，并在玩家会看到的地方确认。**

Core 在启动与资源重载时自动启用内置汉化包。玩家选择「简体中文」后即可使用，翻译资源随 JAR 发布。

## 先找到文本

确认模组及版本、原文、语言键与使用位置。截图有助于判断物品名称、菜单按钮或配置说明的上下文。先区分缺少语言键、已有译文不准确，以及模组硬编码文本。

| 文件 | 用途 |
| --- | --- |
| `localization/overrides/<命名空间>.json` | 按语言键维护需要补充或修正的中文。 |
| `localization/reviewed/` | 初次导入时审核过的英文短语与译文记录。 |
| `localization/fallback-en/<命名空间>.json` | 模组缺少英文资源的已声明文本，例如已注册名称或配置项。 |
| `localization/english-reference.json` | 与已提交汉化对应的英文快照，用于检查格式参数。 |
| `localization/source-notes.json` | 补充 JAR 许可声明未区分的资源许可及其公开来源。 |
| `src/main/resources/localization/assets/` | 最终打包的语言资源。 |
| `src/main/resources/META-INF/sise-localization/` | 来源、协议、署名与命名空间清单。 |

## 修正已有译文

1. 在 `localization/overrides/<命名空间>.json` 中修改对应语言键。
2. 同步资源，再运行只读检查：

```sh
python tools/check_localization.py --sync
python tools/check_localization.py
```

3. 在游戏的对应界面确认显示与换行；资源重载后再次确认。
4. 一起提交源文件、生成的语言资源，以及需要更新的来源记录。

`--sync` 只处理英文快照中已知的键，复制必要的英文补充并更新命名空间清单；不会联网，也不会写入游戏实例。历史源文件中未被本版使用的键会保留在源文件里。

## 补充一个新键

先确认该键确实由目标模组使用。在英文快照中加入原文，在 `overrides` 中加入中文，并在 `provenance.json` 中记录来源。若模组缺少已注册名称或已声明配置项的英文资源，再补充 `fallback-en`。运行同步、检查和游戏验证后提交。

升级模组时，重新核对英文快照。仅新增资源键无法修复模组中的硬编码文字。

## 翻译约定

- 同一物品与动作使用一致术语，按钮先表达动作，提示说明结果。
- 保留 `%s`、`%d`、`%1$s`、`{0}` 等格式参数；调整顺序时使用原文已有的位置索引。
- 保留注册 ID、命令、单位、颜色码及技术标记。不要给有意留空的描述增加文本。
- 结合上下文检查短句，在实际界面确认宽度、换行和完整显示。
- 引入社区或其他模组的译文时，补齐来源、署名和原协议，遵循 [NOTICE.md](../NOTICE.md)。

## 检查的范围

检查器验证 JSON 重复键、文本类型、格式参数、英文补充、源文件同步、来源记录与命名空间清单。它核对仓库中提交的快照，不会扫描玩家后来安装的模组，也不能证明新版本的全部文本已覆盖。

Core 0.1.1+26.1.2 的初次审核记录为：206 个模组 JAR、170 个语言命名空间，最终补充 134 个命名空间的 5,909 条文本。此数据是固定版本的结果。

## 历史导入工具

`tools/` 中除 `check_localization.py` 外的脚本保留了初次整合包迁移流程。它们依赖原工作区布局、审核缓存、旧版模组和测试实例，部分包含固定本地路径；不是克隆仓库后的通用构建步骤。维护者重新导入前应先阅读并调整路径，不要直接在正式实例运行安装或验证脚本。

社区资源固定版本与协议位于[汉化声明](../src/main/resources/META-INF/sise-localization/NOTICE.md)。
